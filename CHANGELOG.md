# Changelog

All notable changes to ChopChopMF are documented here. This file was introduced with version 1.3, so entries for 1.2 and earlier are limited to what could be reliably reconstructed — see the [ChimeraX Toolshed page](https://cxtoolshed.rbvi.ucsf.edu/apps/chimeraxchopchopmf) for the historical release listing.

## 1.4 (2026-09-02)

### Added (this entry listed first, newest work)
- New **Cell Biology** toolbar section (left of "Undo"): three sequence-motif finders, each a thin GUI (`phospho_sites.py`/`signal_peptide.py`/`transmembrane_helix.py`) over a shared, pure scanning module `cellbio.py` (mirrors `scoring.py`'s Qt-free role). Every hit is a **heuristic motif match** (a hand-written regex approximation of a published consensus), not a calibrated predictor's output - see [docs/acknowledgements.md](https://lukasinscience.github.io/ChopChopMF/acknowledgements/#citations-for-cell-biology-motifs) for the exact source (and any deliberate approximation) behind every motif.
  - **Phospho Sites** - 9 kinase consensus motifs (ATM/ATR, PKA, PKC, CDK, CK2, GSK3, MAPK, AKT, AMPK), S/T/Y acceptors only, filtered by pLDDT (disordered) and SASA (exposed).
  - **Signal Peptide** - 6 targeting-signal motifs (NLS mono/bipartite, NES, ER retention, peroxisomal PTS1/PTS2), filtered by SASA; plus a separate N-terminal mitochondrial-presequence charge heuristic (explicitly labeled as this project's own threshold, not a published rule).
  - **TM Helix** - DSSP alpha-helices scored by mean Kyte & Doolittle (1982) hydrophobicity; when ChimeraX's own `mlp` lipophilicity table is available, also reports a SASA-weighted Fauchere & Pliska (1983) score per helix (the [rbvi/chimerax-recipes "helixmlp"](https://rbvi.github.io/chimerax-recipes/helixmlp/helixmlp.html) method) - a stronger membrane-facing signal than residue identity alone.
  - Every hit is written as a real residue attribute (`chopchop_phospho_kinase`, `chopchop_signal_organelle`, `chopchop_tm_helix`), so it shows up in **Investigate** automatically, same convention as every other tool.
  - Fixed a pre-existing, unrelated cosmetic bug found while editing `bundle_info.xml`: a malformed single-line `ChimeraX :: Tool` classifier (4 fields instead of 5) that logged "Malformed ChimeraX :: Tool line in AlphaFold2 skipped" on every install.

### Added (Setup tool, ahead of the correctness fixes below)
- New **Setup** toolbar tool (`chopchop_settings.py`, toolbar section right after "Undo") - a central place for every persistent location ChopChopMF tools save output to, instead of hunting through each tool's own tab:
  - **Shared Locations**: the existing shared **download folder** setting (same one AlphaMissense fetch's/Sequence's own fields already edit), a new **export folder** setting (suggested starting folder for PAE Analysis's/Batch Analysis's/Investigate's CSV/Markdown "Save As" dialogs, replacing a hardcoded `~` in all five of them), and PDBePISA's `.defattr` output folder - now a real persistent setting (`defattr_output_dir`) instead of a plain instance attribute that vanished when the tool closed, so it's visible/changeable here even while PDBePISA isn't open. PDBePISA's own "Change .defattr output folder…" button is gone, replaced by a read-only label that live-updates if changed from here.
  - **Model Annotations (Investigate Sessions)**: per-model **"Save Session As…"** (timestamped snapshot of the `.chopchop.json` "chart file", never touching the live file) and **"Change…"** (load an earlier snapshot back, or redirect to a new file) - moved here from Investigate's main panel and Chart popup, where they lived for one round before this. Investigate itself keeps only a read-only "Annotations file:" label with its own small refresh button.
- Fixed the underlying cause of a real settings-contamination bug: a scratchpad test path had gotten written into the shared, persistent `download_dir` setting during an earlier verification run and stuck around across ChimeraX restarts, so `.chopchop.json`/download-dependent tools pointed at a path the user could never find in Finder. Reset back to the real `~/Downloads` directly in the persisted settings file; the new Setup tool's visible, editable field makes this kind of drift immediately obvious (and easy to fix) going forward instead of silently invisible.
- New `local_readme.md` at the repo root: how to build/preview the local guide with Zensical, and where Claude Code's own temporary test files live (never inside the project tree) - written after the settings-contamination incident above to make that distinction explicit.

### Fixed (this section listed first - a real correctness bug, not cosmetic)
- `pae_analysis.py`: pDockQ, buried area, H-bonds, LIS, cLIS, iLIS, and ipSAE were being written onto **every residue of both entire selected chains**, not just the actual interface - for a two-chain structure this meant the identical value appeared on literally every residue in the model (visible as e.g. "Interface pDockQ = 0.562" repeated across all 1262 rows of an AI-analysis export, reported as looking broken). These are single, pair-level aggregate scores, not per-residue math, so they're now written only onto the actual contact residues (CB-CB <= 8 Å, the same set `compute_contact_residues()`/"Select contacts"/the "Interface contact" flag already use) - everywhere else stays blank, same convention as the new "PAE (Å)" column. Verified with real reference data: previously set on 100% of both chains (648/648 and 923/923 residues), now correctly set on only the actual contact residues (37/648 and 46/923) - re-verified the existing "stale value cleared after switching chain pairs" regression test still passes with the new, narrower scope.
- `annotations.py`/`investigate.py`: the fix above alone wasn't enough to actually clear a Chart/AI-export that had already recorded the old, over-broad values into its durable `.chopchop.json` file - `record_values()` only ever adds/replaces, it never removes a key, so a value written once (even by the bug above) stayed in the file forever and kept reappearing in the Chart even after the live computation was fixed and rerun, merged back in every time the (now-correctly-empty) live attribute was absent. New `AnnotationStore.clear_stale_values()` + a shared `Investigate._merge_stored_and_live()` helper (used by both `_build_chart_rows` and `_build_combined_chart_rows`, covering the Chart table, its CSV export, and the AI-analysis export, which all go through it) now actively removes a residue's stored value for any attribute name that's currently live somewhere else in the same model - i.e. a tool has (re)computed this session, so its absence on a given residue is now authoritative - while leaving alone any attribute that isn't live anywhere in the model right now (an earlier session's data on a freshly-reopened, not-yet-recomputed structure), so durable persistence across a close/reopen is unaffected. **Practical effect for an already-affected structure:** re-running PAE Analysis's Scores tab once (e.g. click "↻ Refresh Scores") for that model is what triggers the cleanup - simply reopening the Chart on stale data it hasn't seen recomputed yet still shows the old numbers, by design.

### Added
- `pae_analysis.py`: the "PAE Contacts" tab can now filter by the actual PAE value (`Limit to residue pairs with PAE ≤`, default 12 Å), not just spatial distance, using ChimeraX's existing `alphafold contacts maxPae` option.
- `pae_analysis.py`: the "PAE Contact Residues" tab now has a "Remove 'PAE Contacts' model after selecting" checkbox instead of always deleting the pseudobond model.
- `pae_analysis.py`: new "Plots" tab with pLDDT-per-residue, ipTM/pTM, and PAE-matrix sections (matplotlib). Each has an "Open Figure" button that draws the current data fresh in its own larger, independent window with a "Save…" button (PNG/PDF/SVG) — nothing is embedded in the tab itself, so it's never too small to read.
- `utils.py`: new `open_figure_dialog()` helper (floating matplotlib figure window with a save-as dialog), reusable by other tools with plots (e.g. `pdbepisa.py`).
- New `scoring.py` module and a dedicated "Scores" tab: **pDockQ** (Bryant, Pozzati & Elofsson, *Nat Commun* 2022, with a color-coded confidence badge using a validated, accessible status palette), **LIS/cLIS/iLIS** (Kim et al., *bioRxiv* 2024, iLIS badged at its published high-confidence threshold), **ipSAE (d0chn variant)** (Dunbrack, github.com/DunbrackLab/IPSAE), and **buried interface area**/**hydrogen bond count** (via ChimeraX's own `measure buriedarea`/`hbonds`) for the chain pair selected in Tab 1. Each score has its own **Select** button that jumps from the number to the actual residues in 3D: "Select contacts" (pDockQ), "Select H-bonds" (colors each H-bond by its own length - shorter/stronger vs. longer/weaker), and "Select confident pairs" (iLIS, selects only the residues in a cLIS-qualifying pair). A **Deselect** button clears the selection, and "Export scores as CSV…" saves the aggregate values. See [docs/acknowledgements.md](https://lukasinscience.github.io/ChopChopMF/acknowledgements/#citations-for-interface-scores) for full citations. pDockQ2, mpDockQ, ipSAE's adaptive d0dom/d0res variants, and salt bridges are intentionally not included yet — pending verification of their exact published constants.

- New **Investigate** tool (`investigate.py`, `annotations.py`): pick a model, then Ctrl+click a residue in the 3D view (or use any tool's Select button) to see every custom ChimeraX residue attribute any tool has recorded for it (e.g. PDBePISA's `residue_score`, ChopMissense's `MissenseScores`), color-coded pLDDT, and a free-text note - a cross-tool "residue dossier." The **Chart** view (its own large window - a full residue table doesn't fit a docked panel) lists every residue of the model at once with a fixed set of columns for every value any ChopChopMF tool can produce (PDBePISA class/ΔG, AlphaMissense, PAE contact/cLIS) - shown blank until that tool has actually been run, so the table itself points out which analyses are still worth doing - plus a live-filtering search box (by residue number), a directly editable Notes column, CSV export, an **"Export for AI analysis…"** button (asks what you want analyzed, then writes a Markdown file with that question up front, references to the ChopChopMF guide, AlphaFold Guide, and ChimeraX FigureStyle guide - with an explicit note to actually read them, not just note them - a plain-language explanation of each column, and any notes - ready to paste into an LLM chat; written locally, nothing sent anywhere by ChopChopMF itself), and a way to save a copy of the underlying `<structure-name>.chopchop.json` notes file (defaults to your ChopChopMF download folder, changeable per model). A new **Plots** tab adds an "Attribute Coverage" heatmap (every residue vs. every value any tool can produce, gray = not recorded yet - spots residues with evidence from several tools at once) and a "Compare Two Values" scatter plot (any two numeric columns, e.g. pLDDT vs. AlphaMissense). `pae_analysis.py`'s "Select contacts"/"Select confident pairs" now also record `chopchop_pae_contact`/`chopchop_pae_clis_confident` as real residue attributes, so they show up in the Chart automatically.
- New `CITATION.cff` (Citation File Format) at the repo root, so GitHub shows a "Cite this repository" button and users have a canonical way to cite ChopChopMF.
- Docs guide can now also be built/previewed with [Zensical](https://zensical.org) (`zensical.toml`, "modern" variant, Inter/JetBrains Mono fonts, teal + custom salmon accent, light mode as the default) alongside the existing `mkdocs.yml`/GitHub Pages pipeline, which is untouched - `zensical serve` for a fast local preview.
- New **Batch Analysis** tool (`batch_analysis.py`): runs PAE Analysis's interface scores (pDockQ, buried area, H-bonds, LIS/cLIS/iLIS, ipSAE d0chn) across many models at once, instead of one chain pair at a time. Two input modes: **Already-open models**, or **Folder of files** - point it at a folder of `.cif`/`.pdb` files and each one is opened, scored, and closed automatically before the next, so a large batch never needs them all open in ChimeraX simultaneously (PAE Analysis itself only ever works with exactly one open model - this mode exists specifically so a folder of many predictions doesn't have to fight that limitation by hand). Pick a chain-role rule once - the same chain letters on every model, or "first chain(s) = side 1, last chain = side 2" (borrowed from `victoria-mischley/PPIScreenML`'s own batch convention, for batches that don't all share one chain-naming scheme; non-protein "chains" like a bound ligand/ion are automatically excluded from both sides) - then **Run Batch** and **Export as CSV…**. For AlphaFold3-server output (`..._model_N.cif` next to `..._full_data_N.json`, the server's own fixed naming convention), the matching PAE file is found and loaded automatically; other formats still need PAE Analysis's own "Load .json file" first, and a model with no PAE data either way is reported as skipped, never guessed at.
- `investigate.py`: the Chart popup now has its own **Model** selector, independent of the Residue tab's - switch which model's Chart you're looking at without closing the popup or disturbing the background window's selection. CSV/AI-analysis/annotations-file export from the popup now always act on whichever model the popup itself currently shows.
- `alphafoldinfo.py`: new **"Attach fetched values to this structure"** button on the AlphaSync tab writes SASA/RSA/Surface/Disorder/Secondary-structure as real ChimeraX residue attributes (so they show up automatically in Investigate's Chart, and work with `color byattribute`/`select`) - but only after verifying, chain by chain, that the UniProt sequence position actually matches this structure's own residue numbering (comparing each position's amino acid); if it doesn't, nothing is attached and the tool explains why (e.g. a cropped or experimental structure, or the wrong UniProt ID).
- `investigate.py`: the "Compare Two Values" scatter plot (Plots tab) is now clickable - click any point to select that residue and jump straight to its Residue-tab dossier. (`utils.open_figure_dialog()` gained an optional `on_pick` callback to support this, backward-compatible for existing callers.)
- `pae_analysis.py`: pDockQ, buried area, H-bonds, and (once a PAE `.json` is loaded) LIS/cLIS/iLIS/ipSAE are now written as real ChimeraX residue attributes every time the Scores tab computes them - not just when a **Select** button is clicked - so they show up in Investigate's Chart/Plots automatically, without an extra manual step. Switching chain pairs correctly clears any stale value left on a chain no longer part of the current pair.
- `annotations.py`/`investigate.py`: the `.chopchop.json` "chart file" now durably records every tool's computed *values* for a residue (not just your free-text notes) - Investigate's Chart snapshots whatever's currently live into this file every time it's opened or refreshed, so a value computed by PDBePISA, PAE Analysis, ChopMissense, or AlphaSync survives a plain close/reopen of the structure (even in a brand new ChimeraX session), instead of only existing for as long as the model stays open. This is generic - a future tool needs no extra code to participate.
- `investigate.py`: new **"Export as CSV… (all models)"** button in the Chart popup - every residue of every currently open model in one combined file (using the fixed known-tool columns, so rows from different models always line up under the same headers).
- `pdbepisa.py`: the ΔG-coloring **defattr** file was written to a bare relative filename (`dg_coloring_output.defattr`), landing wherever ChimeraX's working directory happened to be - unpredictable and easy to lose. Now written next to the loaded PISA XML file, same convention as the tool's other (interface-class) defattr output.
- New **Input & Output Files** guide section (right after "The Toolbar") explaining where ChopChopMF expects to find input (structures, PAE `.json`) and where it saves output (the `.chopchop.json` chart file, `.defattr` files, CSV/Markdown exports) by default, and what's user-changeable.
- `pdbepisa.py`: new **"Change .defattr output folder…"** button (Interface Scoring tab) - overrides where both tabs' `.defattr` files are written; previously always fixed to "next to the loaded XML file" with no way to change it.
- `chopmissense.py`: the AlphaMissense hotspot download now uses the same shared, user-changeable download folder every other ChopChopMF tool already does (`get_settings(session).download_dir`) - previously hardcoded to `~/Downloads` regardless of what the user had set elsewhere, so changing the download folder in AlphaMissense fetch's or Sequence's own field silently didn't affect this tool.
- `utils.py`: pDockQ/iLIS's citable confidence-badge thresholds (previously private to `pae_analysis.py`) moved to shared, reusable helpers (`threshold_badge()`, `PDOCKQ_THRESHOLDS`, `ILIS_THRESHOLD`, etc.) so the exact same green/amber/red verdict can be shown anywhere the score appears, not just in the Scores tab.
- `investigate.py`: the pDockQ and iLIS columns/rows now show the same color-coded confidence badge as PAE Analysis's own Scores tab, both in the Chart table and the per-residue attribute panel - previously shown as plain, uncolored numbers there even though an established threshold already existed.
- `pae_analysis.py`: the ipTM/pTM bar chart (Plots tab) is now colored green/amber/red for >0.8 / 0.6-0.8 / <0.6, the same traffic-light convention documented on the AlphaFold Guide's Confidence Metrics page - previously a single flat color regardless of value.
- `investigate.py`: the Chart/Residue-panel columns for pDockQ, buried area, H-bonds, and the pDockQ contact flag were all labeled "PAE …" even though none of them actually read the PAE matrix (pDockQ derives from contact count + pLDDT only; buried area/H-bonds are pure contact geometry) - only LIS/cLIS/iLIS/ipSAE genuinely use PAE values. Relabeled to "Interface pDockQ"/"Interface Buried area"/"Interface H-bonds"/"Interface contact" to stop implying a PAE dependency that isn't there (the underlying attribute names on disk are unchanged, so existing `.chopchop.json` files still load correctly - only the display label changed).
- `scoring.py`/`pae_analysis.py`/`investigate.py`: new **Contact PAE** score - the *actual* PAE value (Å) read from the matrix, not a derived score, averaged per contact residue over its partners on the other chain (same direction ChimeraX's own `alphafold contacts` uses to color its pseudobonds, i.e. `pae.value(chain1_residue, chain2_residue)`, not symmetrized). Shown in the Scores tab as the average over all contact residues; each contact residue's own value is also written as `chopchop_pae_contact_pae` and shows up individually in Investigate's Chart/Residue panel, colored on the same continuous blue-to-white scale as the PAE Matrix plot (`utils.PAE_CMAP`/`pae_value_colors()`, now shared instead of duplicated). Addresses the fact that pDockQ - despite being the tool's headline number - never actually reads a real PAE value, which read as confusing next to a "PAE" label.

### Fixed
- `pae_analysis.py`: "Load .json file" now uses a proper file picker that links the PAE data directly to the currently open model and verifies the load succeeded, instead of just opening ChimeraX's separate AlphaFold Error Plot panel and assuming success.
- `pae_analysis.py`: the "exactly one open model" error now explains what to do (combine chains into one model) instead of just stating the restriction.
- `pae_analysis.py`: the contact distance field is now an editable spin box (was a fixed 3–10 Å dropdown), allowing intermediate values.
- `pae_analysis.py`: "Load .json file" now opens in the same folder as the currently open structure (`.pdb`/`.cif`) instead of always starting at the home directory, since the PAE `.json` is normally saved right next to it.
- `pae_analysis.py`: residues highlighted by one Select button no longer stay colored/shown once a different Select action is run (or **Deselect** is clicked) - each action now resets everything it previously highlighted back to a neutral color first, so only the current result is ever shown.
- `pae_analysis.py`: new **Open residue table** button on the Scores tab shows the currently selected residues (chain, number, name, pLDDT) in a sortable, exportable popup table (`utils.open_residue_table_dialog()`), for closer inspection than the 3D view or the log alone.
- `investigate.py`: the Chart/Residue tabs no longer show a confusing `pLDDT_score` column/row for AlphaFold-style structures whose mmCIF file embeds its own local per-residue confidence metric - ChimeraX itself registers that as a real `pLDDT_score` residue attribute (unrelated to ChopChopMF), which is numerically a near-duplicate of the pLDDT already shown from the B-factor column. It's now excluded from display (the underlying ChimeraX attribute itself is untouched).
- `alphafoldinfo.py`: the AlphaFold2 tool's coloring button and related messages said "pLDDT score" - shortened to "pLDDT" (pLDDT already is a score, so the word was redundant and read like a second, different value).
- `investigate.py`: the model picker now shows each model's actual filename (e.g. "#1 my_structure.pdb"), not just its bare ChimeraX ID number, so multiple open models are actually distinguishable.
- `pae_analysis.py`: "Load .json file" no longer also pops open ChimeraX's own separate "AlphaFold Predicted Aligned Error" plot window (`plot false` added to the underlying `alphafold pae` command) - redundant clutter now that ChopChopMF's own Plots tab already covers this.
- CSV export could crash with a `UnicodeEncodeError` on some systems, since none of the five places writing a CSV file (`pae_analysis.py`, `investigate.py`, `utils.py` ×2, and the new `batch_analysis.py`) specified an encoding - several export a header containing "Å"/"Δ" (e.g. "Buried area (Å²)", "PDBePISA ΔG"). All five now write with `encoding="utf-8-sig"` (UTF-8 with a BOM) - plain `utf-8` alone stopped the crash but Excel, opening a BOM-less UTF-8 file, still misread those same characters as mojibake ("Buried area (ÃÂ²)"); the BOM is what makes Excel detect UTF-8 correctly.
- `scoring.py`: `compute_hbond_count()` now accepts a set/list of chain IDs for either side (not just a single chain), needed for Batch Analysis's "first chain(s) vs. last chain" rule - backward-compatible for existing single-chain callers.
- `pae_analysis.py`: pDockQ/buried area/LIS/cLIS/iLIS/ipSAE are now rounded (3 decimal places, buried area to 1) once, right where they're computed - previously the Scores tab display rounded for show but the underlying value written to residue attributes, the CSV export, and (via Investigate) the Chart/Residue panel all still carried raw floating-point precision (e.g. `0.7234891827...`).

## 1.3

### Fixed
- `chopalignment.py`: removed a duplicate `fill_context_menu` method whose "Clear" action referenced a non-existent widget and would crash on click.
- `chopalignment.py`: replaced `distutils.dir_util.copy_tree` (removed in Python 3.12) with `shutil.copytree`.
- `chopalignment.py`: model/chain selection in the alignment tool no longer relies on fragile string-length parsing; it now reads the value directly from the dropdown.
- `chopmissense.py`: replaced a hardcoded `/tmp` path with `tempfile.gettempdir()`, fixing the tool on Windows.
- `pdbepisa.py`: interface selection and ΔG coloring no longer hardcode model `#1`; both tabs now have a model selector.

### Security / Robustness
- Added request timeouts to all network calls (UniProt, AlphaMissense, AlphaSync).
- Quoted file paths passed into ChimeraX `run()` commands.
- Added input validation for the sequence/UniProt ID field.
- Added zip-slip protection when extracting downloaded AlphaMissense archives (`utils.safe_extractall`).

### Added
- Tab content in all 9 tools is now scrollable and opens at a comfortable default height; each tab's layout is top-aligned so extra space collects as blank space at the bottom instead of stretching widgets apart.
- Every tab of every tool now has a "📖 Open Guide / Tutorial" button at the top, linking directly to the relevant section of the [online usage guide](https://lukasinscience.github.io/ChopChopMF/usage/) in the user's browser.
- Busy cursor and button-disable feedback during network-bound actions (sequence alignment, AlphaMissense fetch, AlphaSync fetch).
- Error dialogs (in addition to log messages) for the main failure points of each tool's primary action.
- Download folder path is now remembered between sessions (`chopalignment.py`, `chopgetmissense.py`).
- New shared `src/utils.py` module (`make_scrollable`, `make_guide_button`, `busy_cursor`, `show_error`, `safe_extractall`, `get_settings`) to remove duplication introduced by the scrolling/feedback work.

### Changed
- Unified the version string across `bundle_info.xml`, `setup.py`, `src/__init__.py`, and the docs (previously inconsistently at 1.1/1.2).
- Removed dead per-file `BundleAPI` classes in `pae_analysis.py`, `foldseekanalysis.py`, `alphafoldinfo.py`, `pdbepisa.py` (never loaded by ChimeraX; only `src/__init__.py`'s `bundle_api` is used).
- Declared `requests` and `matplotlib` as explicit bundle dependencies.
